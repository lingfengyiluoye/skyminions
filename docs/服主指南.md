## 环境要求

| 组件 | 要求 | 说明 |
|---|---|---|
| **服务端** | Paper 1.21+ | 不支持 Spigot/Bukkit |
| **JDK** | 21+ | 虚拟线程支持 |
| **内存** | 无额外要求 | 瘦 jar，Paper 自动下载依赖 |
| **数据库** | SQLite（默认）/ MySQL | 可选 |

## 安装步骤

### 1. 构建

```bash
git clone https://github.com/lingfengyiluoye/skyminions.git
cd skyminions
mvn clean package
```

### 2. 部署

```bash
cp target/SkyMinions-1.0.0.jar /path/to/server/plugins/
```

### 3. 首次启动

```bash
# 重启服务器
# 插件自动生成 plugins/SkyMinions/ 目录及默认配置文件
```

### 4. 验证

```
/minion stats
```

应看到运行统计信息。

## 全局配置

> 文件：`config.yml`

```yaml
# 全局调度参数
tick-period: 20             # 调度周期（tick），默认 20（1 秒）
max-checks-per-cycle: 48    # 单次方块检查上限（必须 < 50）
max-minions-per-player: 5   # 每玩家仆从上限

# 仆从头颅贴图（base64 纹理）
head-texture: "eyJ0ZXh0dXJlcyI6..."

# 皮肤纹理覆盖（可选）
skins:
  default: ""
  golden: ""
  diamond: ""
  halloween: ""

# 调试模式
debug: false

# 升级是否需要消耗当前等级仆从本体
upgrade-require-previous-body: true

# 收集解锁开关
collection-unlock-enabled: true

# 玩家活动半径（方块）：半径内无玩家则休眠，0 = 永不休眠
player-scan-radius: 48

# 仆从间最小间距（水平切比雪夫距离），0 = 不限制
min-placement-distance: 1

# 稀有掉落广播
rare-drop-broadcast: true
```

### 关键参数说明

| 参数 | 默认值 | 说明 |
|---|---|---|
| `max-minions-per-player` | 5 | 基础上限，可与里程碑加成叠加 |
| `player-scan-radius` | 48 | 对齐 Hypixel，0 = 永不休眠 |
| `min-placement-distance` | 1 | 1 = 允许贴身连放（只禁同格） |
| `upgrade-require-previous-body` | true | true = 升级需消耗当前等级本体 |
| `collection-unlock-enabled` | true | true = 需收集产物达阈值才解锁 |

## 仆从类型配置

> 文件：`config.yml` → `types:` 段

### 新增仆从类型

```yaml
types:
  钻石仆从:
    behavior: MINING                    # 行为原型（7 种）
    display-name: "钻石仆从"             # 显示名
    icon: DIAMOND                       # 图鉴图标材质
    max-level: 12                       # 最高等级
    cooldown-ticks: [960, 900, 840, 760, 660, 540, 480, 420, 360, 300, 240, 180]
    sell-price-per-unit: 6.0            # 单价（Vault 售卖）
    product: DIAMOND                    # 代表产物
    targets: [DIAMOND_ORE, DEEPSLATE_DIAMOND_ORE]  # 基础目标方块
    harvest-cap: 4                      # 单次采集上限
    upgrade-recipe:                     # 升级配方（Tier 1→2 基础数量）
      DIAMOND: 64
      'enchanted:diamond': 2
    upgrade-cost-growth: 1.25           # 陡增系数（每级 ×1.25）
    rare-drop: ECHO_SHARD               # 稀有掉落
    rare-drop-chance: 0.003             # 稀有掉落概率（0~1）
    unlock-amount: 150                  # 收集解锁阈值
```

### 行为原型（behavior）

| 行为 | 说明 | 适用场景 |
|---|---|---|
| `MINING` | 模拟采集（只读方块，不破坏） | 矿石类 |
| `FARMING` | 模拟收割（读取 Ageable 生长阶段） | 农作物类 |
| `FORAGING` | 真实连锁砍伐 + 自动补种 | 木材类 |
| `FISHING` | 模拟钓鱼（附近有水即工作） | 钓鱼类 |
| `COMBAT` | 真实击杀优先 + 模拟回退 | 怪物类 |
| `RANCHING` | 纯模拟畜牧（战利品表 roll） | 畜牧类 |
| `GENERATOR` | 生成→采集循环 | 圆石类 |

### 分级解锁目标（targets-by-tier）

```yaml
铁矿仆从:
  targets: [STONE]                    # 基础目标（1 级即可）
  targets-by-tier:
    4: [IRON_ORE, DEEPSLATE_IRON_ORE] # 4 级解锁铁矿
    8: [DIAMOND_ORE]                  # 8 级解锁钻石矿
```

### 分阶配方覆盖（upgrade-recipe-at）

```yaml
煤矿仆从:
  upgrade-recipe:
    COAL: 32
    'enchanted:coal': 2
  upgrade-recipe-at:                  # 特定等级覆盖配方
    '12':
      COAL: 256
      'enchanted:coal': 6
      EMERALD: 24                     # 稀有掉落回流
```

### 战斗型定向目标（preferred-targets）

```yaml
僵尸仆从:
  behavior: COMBAT
  preferred-targets: [ZOMBIE, ZOMBIE_VILLAGER, HUSK, DROWNED]
```

### 畜牧型指定畜种（ranch-animal）

```yaml
牛仆从:
  behavior: RANCHING
  ranch-animal: COW                   # 指定单一畜种
```

## Collection 里程碑配置

> 文件：`config.yml` → `collections:` 段

```yaml
collections:
  enabled: true
  milestones: [50, 100, 250, 500, 1000, 2500, 5000, 10000]
  coins-base: 100                     # 第 n 个里程碑 = coins-base × n
  slot-milestones: [3, 5, 7]          # 第 3/5/7 个里程碑各 +1 槽位
  max-bonus-slots: 5                  # 多资源叠加总上限
```

**金币计算示例：**
- 第 1 个里程碑：100 × 1 = 100 金币
- 第 2 个里程碑：100 × 2 = 200 金币
- 第 3 个里程碑：100 × 3 = 300 金币 + 仆从槽位 +1

## 离线收益配置

> 文件：`config.yml` → `offline-production:` 段

```yaml
offline-production:
  enabled: true        # 总开关
  max-hours: 24        # 单次结算最长回溯（小时）
  rate-percent: 100    # 基础速度折扣（50~100）
  min-seconds: 180     # 低于此闲置秒数不结算
```

**三道平衡锁：**
1. 仓储天花板：仓库满 = 不再累计
2. 基础速度：不吃燃料/倍率/布局加成
3. 燃料燃烧：闲置时长从燃料扣除

```yaml
storage-gui:
  title: "<gold>{name} <white>{tier}</white></gold>"
  info:
    title: "<green>仆从信息</green>"
    lore:
      - "<gray>▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬</gray>"
```

支持 MiniMessage 颜色标签：`<gold>` `<red>` `<green>` `<gray>` `<aqua>` 等。

```yaml
layout:
```

## 权限管理

### 权限节点

| 权限 | 默认值 | 说明 |
|---|---|---|
| `hcs.minions.admin` | op | 管理命令 |
| `hcs.minions.use` | true | 使用仆从 |
| `hcs.minions.type.<类型名>` | true | 按类型控制 |
| `hcs.minions.limit.<n>` | — | 数量上限（取最大 n） |

### LuckPerms 示例

```bash
# VIP 组最多 20 个仆从
/lp group vip permission set hcs.minions.limit.20 true

# 禁止某组使用钻石仆从
/lp group builder permission set hcs.minions.type.钻石仆从 false

# 给玩家单独设置上限
/lp user Steve permission set hcs.minions.limit.10 true
```

### 权限叠加规则

- `limit` 取玩家拥有的**最大 n 值**
- 基础上限（`max-minions-per-player`）+ 里程碑加成 = 实际上限
- 管理员（`hcs.minions.admin`）不受限制

## 数据库配置

> 文件：`config.yml` → `database:` 段

### SQLite（默认）

```yaml
database:
  type: sqlite
  sqlite-file: "minions.db"
```

- 零配置，文件存储在 `plugins/SkyMinions/minions.db`
- 适合小型服务器（< 100 个仆从）

### MySQL

```yaml
database:
  type: mysql
  host: 127.0.0.1
  port: 3306
  database: minions
  user: root
  password: "your_password"
  pool-size: 4
```

- 适合大型服务器
- HikariCP 连接池
- 建议 `pool-size` 不超过 8（虚拟线程特性）

### 数据迁移

SQLite → MySQL：
1. 停止服务器
2. 配置 MySQL 连接信息
3. 使用 SQLite 导出工具导出数据
4. 导入到 MySQL
5. 启动服务器

- 无需硬依赖
- Bukkit 权限自动联动
- `/lp tree` 搜索 `minions` 查看所有节点

## 性能优化

### 调度器优化

- `tick-period: 20`（默认）：每秒检查一次
- `max-checks-per-cycle: 48`：单次方块检查上限（硬限制 < 50）
- 全局单调度器，O(n) 遍历 + O(1) 短路

### 方块搜索优化

- 两阶段螺旋扫描：近处每周期必查，远处游标推进
- 邻接+随机，硬上限 < 50
- 只读方块类型，不产生光照重算/方块更新包

### 数据库优化

- 内存缓存 + CAS 脏标记 + 批量落库
- 按 id 条带锁串行化写操作
- 虚拟线程 IO，主线程零阻塞

### 建议配置

| 仆从数量 | 推荐配置 |
|---|---|
| < 50 | 默认配置即可 |
| 50-200 | `tick-period: 20`，SQLite |
| 200-500 | `tick-period: 40`，MySQL |
| 500+ | `tick-period: 40`，MySQL，考虑分服 |

## 故障排除

### Q: 仆从不工作

**检查清单：**
1. `/minion stats` 确认插件正常运行
2. 检查 `debug: true` 开启调试日志
3. 确认范围内有可采集目标
4. 确认仓库未满（满仓停工）
5. 确认范围内有玩家（`player-scan-radius`）
6. 检查权限：`hcs.minions.type.<类型名>`

### Q: 仆从消失

**可能原因：**
- 盔甲架被 `/kill` 或其他插件移除
- 区块卸载导致实体丢失（正常情况，重新加载区块后自愈）
- 使用 `/minion purge-orphans` 清理残留实体

**数据安全：**
- 仆从数据存储在数据库，实体丢失不影响数据
- 重启后自动重生盔甲架

### Q: 升级失败

**检查清单：**
1. 确认材料数量足够
2. 确认是否需要当前等级本体（`upgrade-require-previous-body`）
3. 确认材料类型正确（原版/附魔资源/CraftEngine）
4. 检查 `upgrade-recipe-at` 是否有等级覆盖

### Q: 自动售卖不工作

**检查清单：**
1. 确认已安装 Vault
2. 确认 `economy.enabled: true`
3. 确认装备了售卖模块或 `auto-sell-on-full: true`
4. 检查经济插件是否正常

### Q: 离线收益不结算

**检查清单：**
1. 确认 `offline-production.enabled: true`
2. 确认闲置时间 > `min-seconds`（默认 180 秒）
3. 确认仓库有空位（满仓不结算）
4. 检查服务器日志是否有错误

### Q: 附魔资源不识别

**检查清单：**
1. 确认物品有 PDC 标记（`minion_enchanted` 键）
2. 确认是通过 `/minion give` 或超级压缩模块产出的
3. 普通原版物品不会被误判为附魔资源

### Q: 性能问题

**排查步骤：**
1. `/minion stats` 查看已放置仆从数量
2. 检查 `max-checks-per-cycle` 是否过大
3. 开启 `debug: true` 查看日志
4. 考虑增加 `tick-period` 减少检查频率
5. 考虑使用 MySQL 替代 SQLite

## 从旧版本迁移

### 英文 key → 中文 key

旧版本使用英文 key（如 `miner`、`farmer`），新版本使用中文 key（如 `煤矿仆从`、`小麦仆从`）。

**迁移方式：**
- 自动兼容：`LEGACY_ALIASES` 映射旧 key 到新 key
- 数据库数据自动迁移，无需手动操作
- 权限节点自动适配

### 配置文件更新

1. 备份旧配置
2. 删除旧配置文件
3. 启动服务器生成新配置
4. 手动合并自定义配置

### 数据库迁移

SQLite → MySQL：
1. 停止服务器
2. 导出 SQLite 数据
3. 配置 MySQL 连接
4. 导入数据
5. 启动服务器

## 最佳实践

1. **定期备份**：备份 `plugins/SkyMinions/` 目录
2. **监控日志**：关注 `SkyMinions` 相关日志
3. **渐进部署**：先在测试服验证配置
4. **权限规划**：提前规划权限组和上限
5. **性能监控**：定期执行 `/minion stats` 检查运行状态
6. **热重载优先**：配置修改优先用 `/minion reload`，避免重启服务器

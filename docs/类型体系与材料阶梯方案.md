# 类型体系重构 + 升级材料阶梯 · 设计方案 v1

> 目标：① 从 7 个"合并型"仆从扩展为 **~39 个按资源细分的仆从类型**（对齐 Hypixel 的内容广度）；
> ② 升级材料全面借鉴 Hypixel 的"基础→浓缩→顶阶稀有"阶梯，但**使用原创命名与原版物品载体**。
> 本文为方案，未经确认不进入实现。

---

## 一、现状与差距

| 维度 | 现状 | Hypixel | 差距定性 |
|---|---|---|---|
| 仆从类型数 | **7 个**（矿工/农夫/伐木/钓鱼/猎魔/牧民/圆石匠），一个类型吃多种资源 | **50+ 个**，一种资源一个专属仆从 | 内容广度不足 |
| 类型定义方式 | Java 枚举硬编码（加类型要改代码） | 数据驱动 | 架构瓶颈 |
| 升级材料 | 单一基础资源 ×1.25 陡增曲线 | 基础资源 → 浓缩形态 → 顶阶稀有物，阶梯式换挡 | 缺乏"阶段感" |

## 二、类型体系重构（架构层）

### 2.1 核心思想：行为与身份分离

```
行为原型 MinionBehavior（7 个，枚举，对应现有 7 个策略类）
   MINING      统计挖掘（摆什么产什么）
   FARMING     统计农耕（成熟判定+自动开垦）
   FORAGING    真实连锁伐木+补种
   FISHING     钓鱼模拟
   COMBAT      猎魔（真实击杀优先+模拟回退）
   RANCHING    畜牧模拟（战利品表 roll）
   GENERATOR   圆石生成循环

仆从类型 MinionType（枚举 → 改造为不可变数据类 + 静态注册表）
   字段：key / displayName / behavior / category / icon
   来源：完全由 config.yml types: 段驱动，加载时注册
   加新类型 = 写一段 YAML，零 Java 改动
```

### 2.2 关键改造点（已逐一定位）

| 触点 | 改法 |
|---|---|
| 策略接口 `type()` | 改为 `behavior()` 返回 MinionBehavior；注册表按行为查表 |
| `Minion.type()` | Minion 内部改持 `String typeKey`，`type()` 每次从注册表现取（热重载安全，Map 查找 O(1)） |
| 持久化 | **MinionData 本就存字符串 key，无需迁移** |
| EntityService 盔甲架配色 | 按 behavior 配色（同行为同类色），后续可扩 per-kind 颜色 |
| GUI `showLayout()` 对 COBBLE/FARMER 的判断 | 改判 behavior |
| CollectionGui `values()` | 改 `MinionType.all()`（LinkedHashMap 保序） |
| 命令 Tab 补全 | 同上 |
| 静态注册表热重载 | 与 GuiText 同款 volatile 整体替换模式 |
| 未注册 key 兜底 | 内置 fallback 类型（防第三方库改档崩溃） |

### 2.3 存档与权限兼容（零成本迁移）

- **老 7 个 key 全部保留并"特化"**：`miner`→煤矿仆从、`farmer`→小麦仆从、`lumberjack`→橡木仆从、`slayer`→僵尸仆从、`rancher`→养牛仆从、`fisher`/`cobble` 不变。
  → 现有数据库里的 2 个仆从、玩家手里的生成物、权限授予**全部无缝延续**。
- 新类型用新 key（如 `iron_minion`）。权限 `hcs.minions.type.<key>` 自动套用同一体系；
  paper-plugin.yml 预登记全部 39 个 default:true。

### 农业 FARMING（8）
小麦*/胡萝卜/马铃薯/南瓜/西瓜/甜菜/可可/下界疣 —— 成熟判定走 Ageable，
稀有掉落示例：南瓜→金胡萝卜、西瓜→附魔金苹果、下界疣→远古残骸。

### 林业 FORAGING（8）
橡木*/白桦/云杉/丛林/金合欢/深色橡木/樱花/红树 —— 复用真实连锁砍伐+补种，
targets 收敛到单一树种（纯林经营，补种树苗自动对应）。

### 钓鱼 FISHING（1）
钓鱼郎* 保持唯一（Hypixel 亦然）。

### 战斗 COMBAT（7）
僵尸*/骷髅/苦力怕/蜘蛛/末影人/烈焰人/史莱姆 ——
新增可选配置 `preferred-targets:`，优先锁定同名怪（无则回退任意敌对）；
离线结算走通用池。Boss 豁免逻辑不变。

### 畜牧 RANCHING（4）
养牛*/绵羊/蛋鸡/生猪 —— 新增可选配置 `ranch-animal:` 指定单一畜种
（牛=牛肉+皮革、羊=羊肉+羊毛、鸡=鸡肉+羽毛、猪=猪排），不再随机混池。

### 生成器 GENERATOR（1）
圆石仆从* 保持唯一。

`带 * 为老 key 特化，存档自动兼容。合计 10+8+8+1+7+4+1 = 39`

## 四、升级材料阶梯（内容层，借鉴 Hypixel 但原创命名）

### 4.1 三阶命名体系（名字不同，机制同源）

| 阶 | 我们的叫法 | 载体（全部原版物品，零新增依赖） |
|---|---|---|
| 一阶 | **基础材料** | 资源本身（煤炭/粗铁/小麦…） |
| 二阶 | **精块**（浓缩 9:1） | 原版方块：煤炭块/铁块/粗铁块/金块/粗金块/铜块/粗铜块/红石块/青金石块/钻石块/绿宝石块/干草块/骨头块/黏液块/石英块/西瓜/雪块… |
| 三阶 | **秘藏**（顶阶限定） | 各类型专属稀有掉落（回流机制，上期已实现 `upgrade-recipe-at`） |

> 在仆从升级语境下，MaterialNames 将给这些方块配置**语境化别名**
> （如 COAL_BLOCK 显示为「煤炭精块」、HAY_BLOCK 显示为「麦穗精块」）——
> 用原版物品、讲自己的名字，服主也可经 CraftEngine 自定义 id 完全替换外观。

### 4.2 曲线设计（以煤矿仆从为例，max-level 12）

| 升级段 | 配方来源 | 内容示意 |
|---|---|---|
| 1→4 | 基础 ×growth¹·²⁵ | 煤炭 64 / 圆石 32 |
| 5→7 | 基础陡增 | 煤炭 128→256… |
| 8（覆盖行） | `upgrade-recipe-at.'8'` | 煤炭 128 + **煤炭精块 16** |
| 10（覆盖行） | `'10'` | 煤炭 192 + 煤炭精块 32 + **绿宝石 8**（稀有回流） |
| 12（终阶覆盖） | `'12'` | XI 本体 ×1 + 煤炭精块 64 + 绿宝石 16 |

- 每类 2~3 条覆盖行即可拉出完整阶梯，YAML 约 10 行/类；
- 数值统一走现有 growth 引擎与原子扣除链路，GUI 对比卡自动展示新行。

### 4.3 配套小改造

- MaterialNames 补录约 15 个方块的语境化别名（纯映射表追加）；
- 升级对比卡最多 3 行材料的限制放宽到 4 行（顶阶配方材料更多）；
- 其余（扣除/GUI/离线/图鉴）零改动——全部复用既有引擎。

## 五、实施切分与验收

| 阶段 | 内容 | 验收标准 | 风险 |
|---|---|---|---|
| 一 | 行为/身份分离重构（~20 文件机械改造 + 注册表） | mvn test 全绿；老档 2 仆从照常加载；7 老 key 行为不变 | 中（触点多但均为机械替换） |
| 二 | 39 类 YAML 编写 + 图鉴翻页实测 + MaterialNames 别名 | 进服图鉴两页完整、放置/工作/离线结算逐类抽查 | 低（纯数据） |
| 三 | 材料阶梯全量覆盖行 + 对比卡 4 行适配 | 任选 3 类实测 8/10/12 级配方显示与扣除正确 | 低 |

预计影响文件：Java 约 22 个（其中测试 3 个）、config.yml 全面重写、MaterialNames 追加、paper-plugin.yml 权限补登。

## 六、待你拍板的三个决策点

1. **老 key 特化方向**是否认可？（miner=煤矿、farmer=小麦、slayer=僵尸、rancher=养牛……）
   若你希望老 key 另有指派，现在说成本最低。
2. **战斗/畜牧细分粒度**：按上表 7+4 拆，还是先保持 2 个合并型、其余 30 类先行？
3. **精块命名**：「煤炭精块/麦穗精块」这套命名风格 OK？还是想要「压缩煤炭」「精华煤炭」等其他风格？
